# 01. 요구사항 명세 — Dice Duel v1.0

> Part 1 · TC-002 · 01 요구사항 검토
> 작성: 김성환 · 확정일: 2026-10-26

플레이어와 컴퓨터가 주사위를 던져 합이 큰 쪽이 이기는 미니게임이다. 매치 결과를 기록하고 통계를 보여준다.
이 문서의 규칙 ID(R-xx)는 테스트 케이스, Gherkin 태그(`@R-02`), 결함 리포트에서 그대로 참조한다.

## 1. 게임 규칙 (Rule)

| ID | 규칙 | 검증 포인트 |
|---|---|---|
| R-01 | 라운드마다 플레이어와 컴퓨터가 같은 개수의 주사위를 던져, 눈의 합이 큰 쪽이 라운드 승리 | 합 비교, 양쪽 주사위 개수 동일 |
| R-02 | 합이 같으면 모든 주사위 눈이 같은 쪽이 승리한다. 2개 매치는 **더블**(예: [3,3]), 3개 매치는 **트리플**(예: [2,2,2])만 해당한다. 양쪽 모두 해당하거나 모두 해당하지 않으면 **무승부** | 3개 매치의 [4,4,1]은 트리플이 아님 |
| R-03 | 먼저 3라운드를 이긴 쪽이 매치 승리. 3승 즉시 매치가 끝난다. 무승부 라운드는 승수에 포함하지 않는다 | 3승 직후 종료, 무승부 라운드 무시 |
| R-04 | 10라운드가 끝나도 3승이 없으면 승수가 많은 쪽이 승리, 같으면 매치 무승부 | 10라운드 종료 판정 (예: 2승 2패 6무 → 무승부) |
| R-05 | 주사위 개수는 2개 또는 3개. 매치 시작 전에만 고를 수 있다 | 그 외 값 거부, 매치 중 변경 불가 |
| R-06 | 닉네임은 2~10자, 한글·영문·숫자만 허용. 앞뒤 공백도 허용하지 않는다. 그 외는 매치 시작을 거부하고 **ERROR log**를 남긴다 | 경계값 1·2·10·11자, 특수문자, 공백 |
| R-07 | 주사위는 **서버**에서 굴린다. 매치마다 seed를 저장하고, 같은 seed면 같은 결과가 나온다. 특정 눈이 필요한 테스트는 **테스트 모드 전용 API**로 다음 라운드의 눈을 지정한다 | seed 재현성, 테스트 모드가 아니면 지정 API 거부 |
| R-08 | 매치가 끝나면 던지기 불가. 끝난 매치에 던지기 요청이 오면 거부하고 **ERROR log**를 남긴다 | 화면 버튼 비활성화 + 서버 거부 |
| R-09 | 던지기 요청에는 라운드 번호가 들어간다. 같은 라운드에 요청이 중복되면 **한 번만 처리**하고 나머지는 거부하며 **WARN log**를 남긴다 | 동시 요청 2건 → 1건 성공, 1건 거부 |

## 2. 통계 규칙 (Statistics)

| ID | 규칙 |
|---|---|
| S-01 | 매치 기록 Grid는 닉네임(부분 일치)·기간으로 필터하고, 시작 시각·닉네임·결과·라운드 수로 정렬한다 |
| S-02 | 합계 분포 Chart는 주사위 개수별로 **실제 분포**(플레이어·컴퓨터의 모든 라운드 합. 단, 테스트 모드로 눈을 지정한 라운드는 제외)와 **이론 분포**를 함께 보여준다 |
| S-03 | 분포 검증 기준: 표본(합계) 5,000개 이상일 때 각 합계의 실제 비율이 이론 비율과 **±2%p 이내** |
| S-04 | 닉네임별 승률 = 승리 매치 수 ÷ 끝난 매치 수. 진행 중인 매치는 제외한다. 승률 높은 순으로 순위를 매기고, 같으면 끝난 매치가 많은 순, 그다음 닉네임 순 |

시각은 한국 시간(KST)으로 표시한다.

## 2-1. 화면 규칙 (User Interface)

| ID | 규칙 |
|---|---|
| U-01 | 게임 화면에 게임 규칙(R-01~R-06의 요점)을 항상 보여준다. 문구는 이 명세와 같아야 한다 (예: "먼저 3라운드를 이기면 매치 승리", "닉네임 2~10자") |
| U-02 | 통계 화면의 매치 기록 Grid는 처음에 현재 정렬 기준으로 **20건**만 보여주고, "더보기"를 누를 때마다 20건씩 추가한다. 보여준 건수와 전체 건수를 함께 표시하고(예: "20 / 205건"), 다 보여주면 "더보기"를 숨긴다. 매치 번호는 게임 화면과 같은 `#번호` 형식으로 표시한다 |

## 3. API 요약

| 메서드 | 경로 | 설명 | 실패 시 |
|---|---|---|---|
| POST | `/api/matches` | 매치 시작 `{nickname, dice_count, seed?, source?, created_at?}`. `created_at`은 테스트 모드에서만 반영 (초기 데이터용) | 400 (R-05, R-06) |
| GET | `/api/matches/{id}` | 매치와 라운드 결과 조회 (화면 값 검증용) | 404 |
| POST | `/api/matches/{id}/throw` | 던지기 `{round_no}` | 404, 409 (R-08, R-09) |
| GET | `/api/matches` | 매치 목록 (S-01 필터·정렬, U-02 `limit`·`offset`). 전체 건수는 응답 헤더 `X-Total-Count` | — |
| GET | `/api/stats/sum-distribution?dice_count=2` | 합계 분포 (S-02) | — |
| GET | `/api/stats/players` | 플레이어별 승률 (S-04) | — |
| POST | `/api/test/next-roll` | **테스트 모드 전용**. 다음 라운드 눈 지정 `{match_id, player, cpu}` | 403 (테스트 모드 아님) |
| GET | `/health` | 상태 확인 (Sanity용) | — |

## 4. 검토하면서 정한 것 (모호했던 점과 결정)

| # | 질문 | 결정 | 이유 |
|---|---|---|---|
| Q-1 | 3개 매치에서 2개만 같은 눈([4,4,1])도 "같은 눈" 우대를 받나? | 받지 않는다. 2개 매치는 더블, 3개 매치는 트리플만 | "모든 주사위 눈이 같은 쪽"의 문자 그대로. 오해를 막기 위해 R-02에 예시를 명시 |
| Q-2 | seed만으로 Gherkin의 "[3,3] vs [2,4]" 같은 특정 상황을 만들 수 있나? | 없다. 테스트 모드 전용 눈 지정 API를 둔다 | seed는 재현성만 보장하고 원하는 눈을 고를 수 없음 |
| Q-3 | 서버를 여러 대 띄우면 seed 결과가 달라지지 않나? | 매치별 seed를 DB에 저장하고, 라운드 눈은 `seed + 라운드 번호`로 계산 | 어느 서버가 처리해도 같은 결과 |
| Q-4 | 같은 라운드에 던지기가 두 번 오면? (더블클릭, 재전송) | 요청에 라운드 번호를 넣고, 이미 처리한 라운드면 거부 (R-09 신설) | "중복 요청 1회 처리" TC에 근거 규칙이 필요 |
| Q-5 | 잘못된 닉네임은 log를 남기나? | ERROR log (R-06) | Log 모니터의 ERROR 필터링 대상 (TC-003 Server) |
| Q-6 | 분포가 "이론과 일치"의 기준은? | 표본 5,000개 이상, 각 합계 ±2%p (S-03) | 기준이 없으면 PASS/FAIL 판정 불가 |
| Q-7 | 규칙을 모르는 사용자가 "몇 승이면 끝나는지" 알 수 있나? | 게임 화면에 규칙 안내를 둔다 (U-01 신설) | 규칙이 화면에 없으면 3승 직후 매치가 끝나는 것을 사용자가 오류로 오해할 수 있음 |
| Q-8 | 테스트 API로 지정한 눈도 합계 분포에 들어가나? | 제외한다 (S-02) | 사람이 고른 눈은 무작위가 아니므로 S-03 분포 검증을 오염시킴 |
