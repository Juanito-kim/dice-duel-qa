## 읽는 법

- **기법**: BVA = 경계값 분석, EP = 동등 분할, DT = 결정 테이블, ST = 상태 전이, CMP = 화면·API·DB 값 비교, EXP = 탐색·시나리오
- **수행 (자동화 여부)**: UI = 화면 조작 (Selenium 자동화 대상), API = API 호출, DB = DB 직접 조회, 수동 = 사람이 확인, 성능 = TC-004에서 수행
- 특정 눈이 필요한 TC는 테스트 모드 API(`POST /api/test/next-roll`)로 눈을 지정한다 (R-07)
- 결과(PASS / FAIL / Blocked)는 [05-test-results.md](05-test-results.md)에 기록한다

## 공통 사전 조건

- `docker compose up -d`로 db·app·lb가 healthy이고, 게임 화면 http://localhost:8080 이 열린다
- 앱이 테스트 모드(`TEST_MODE=true`)로 떠 있다 (TC-D02 제외)
- 초기 데이터(봇 10명의 매치 약 200건, 진행 중 매치 포함)가 들어 있다
- 영역별 추가 사전 조건은 각 표 위에 적는다

## 대표 TC (기능별 1건)

전체 TC는 모두 수행하지만, 포트폴리오·README에는 기능별로 **대표 1건**만 소개한다. 각 대표 TC는 서로 다른 테스트 기법을 보여주도록 골랐다. 아래 표에서는 ★로 표시했다.

| 기능 | 대표 TC | 무엇을 보여주나 | 기법 |
|---|---|---|---|
| 매치 시작 | ★ TC-A03 닉네임 10자 허용 | 입력 경계값을 1·2·10·11자로 나눠 검증 | 경계값 분석 |
| 라운드 판정 | ★ TC-B05 합 같음, 둘 다 더블 → 무승부 | 조건 조합을 결정 테이블로 빠짐없이 도출 | 결정 테이블 |
| 매치 진행·종료 | ★ TC-C01 3승 즉시 종료, 던지기 비활성화 | 상태가 바뀌는 시점과 화면 반응을 함께 검증 (Selenium) | 상태 전이 |
| 중복 던지기 | ★ TC-E02 같은 라운드 동시 요청 | 동시성 문제를 부하 상황에서 검증 | 동시성·성능 |
| 통계 | ★ TC-F13 진행 중 매치는 승률에서 제외 | 화면 값을 DB 직접 조회 값과 비교 | 데이터 비교 |
| 사용자 흐름 | ★ TC-G01 3승 전에 페이지를 닫은 매치 | 기대 결과를 정할 수 없는 지점을 찾아 명세 이슈로 전환 | 시나리오·탐색 |

seed 재현성(D)은 다른 TC의 전제 조건이라 대표로 따로 소개하지 않는다.

## C. 매치 진행·종료 (R-03, R-04, R-08) — 상태 전이

사전 조건: 주사위 2개 매치를 새로 시작한다. 라운드마다 눈 지정 API로 결과를 정한다.

```
진행 중 ──(3승 달성)──────────────▶ 종료 (승자)
   │ └─(10라운드, 3승 없음)───────▶ 종료 (승수 비교: 승자 또는 무승부)
   └─(던지기)──▶ 진행 중           종료 ──(던지기)──▶ 거부 409 + ERROR log
```

| TC ID | 규칙 | 제목 | 절차 | 기대 결과 | 기법 | 수행 |
|---|---|---|---|---|---|---|
| ★ TC-C01 | R-03, R-08 | 3승 즉시 종료 | 플레이어 승 눈을 3번 지정해 던지기 | 3라운드 후 "매치 종료 · 플레이어 승리", 던지기 버튼 비활성화 | ST | UI |
| TC-C02 | R-03 | 무승부 라운드는 승수 미포함 | 무승부 눈 2번 → 플레이어 승 눈 3번 | 5라운드에 종료, 스코어 3:0 | ST | UI |
| TC-C03 | R-04 | 10라운드 동률 → 매치 무승부 | 플레이어 승 2, 컴퓨터 승 2, 무승부 6 지정 | 10라운드 후 "매치 종료 · 무승부" | ST | API |
| TC-C04 | R-04 | 10라운드 승수 많은 쪽 승 | 플레이어 승 2, 컴퓨터 승 1, 무승부 7 지정 | 10라운드 후 "매치 종료 · 플레이어 승리" | ST | API |
