# SPEC-001 도중에 떠난 매치의 처리 규칙이 명세에 없음

| 항목 | 내용 |
|---|---|
| 유형 | **Spec Issue** (명세 누락 — 기대 결과를 정할 수 없음) |
| 상태 | **PO 결정 대기** |
| 관련 규칙 | 없음 (빈틈). 영향 받는 규칙: [S-01](../01-requirements.md) 매치 기록, [S-04](../01-requirements.md) 승률 |
| Blocked TC | ★ [TC-G01](../02-test-cases.md) |
| 발견 경로 | 유저 시나리오 [US-03](../02-user-scenarios.md) "매치 도중에 페이지를 닫고 떠난다" 작성 중 |
| 발견 | 2026-10-26 (앱 검토 중 작성자가 처음 제기), 2026-10-27 기능 검증에서 증거 확보. **일부러 만든 이슈가 아님** |
| 작성 | QA 김성환 · PO 역할도 작성자가 겸함 (포트폴리오 환경) |

## 현상
사용자가 3승 전에 브라우저를 닫으면 그 매치는 **영원히 "진행 중"(IN_PROGRESS)** 으로 남는다.
명세에는 이 상황의 규칙(언제 끝난 것으로 볼지, 기록을 남길지, 통계에 넣을지)이 없어서, TC-G01의 기대 결과를 쓸 수 없다.

## 증거
- DB: 하루 넘게 "진행 중"인 매치 2건. 가장 오래된 것은 **#53 유노, 10/22 시작, 1라운드에서 멈춤** (5일 경과)
  ```sql
  SELECT id, nickname, rounds_played, created_at FROM matches
  WHERE status = 'IN_PROGRESS' AND created_at < now() - interval '1 day' ORDER BY created_at;
  ```
- 통계 화면 매치 기록: 며칠 전 매치가 주황색 "진행 중" 배지로 계속 보인다
- Sanity 테스트도 확인용 매치를 1라운드만 진행하고 두므로 같은 매치가 계속 쌓인다 ([04-sanity.md](../04-sanity.md))

## 영향
- **통계 신뢰도**: 매치 기록에 끝나지 않는 매치가 계속 쌓여, "진행 중"이 정말 진행 중인지 버려진 것인지 구분할 수 없다.
- **[BUG-003](BUG-003.md)과 겹침**: 승률 계산이 진행 중 매치를 잘못 포함하는 결함이 있어, 버려진 매치가 쌓일수록 승률·순위 오류가 커진다.
- **테스트 판정 불가**: 이탈 관련 TC를 PASS·FAIL로 판정할 근거가 없다.

## 관련 부서에 묻는 질문 (PO·기획·개발)
1. 마지막 활동 후 **얼마나 지나면** 떠난 것으로 볼까? (예: 10분)
2. 떠난 매치의 **기록을 남길까, 지울까?**
3. 떠난 매치를 **승률·통계에 넣을까?** 넣는다면 패배로 볼까?
4. 같은 닉네임으로 돌아오면 **이어하기**를 제공할까?

## 개선안 비교

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 중단 상태로 표시 | 마지막 활동 후 일정 시간이 지나면 `ABANDONED`(중단). 기록은 남기고 승률에서 제외. 중단된 매치에 던지기는 거부 | 기록이 남아 추적 가능. 규칙이 명확해 TC로 쓰기 쉬움 | 상태 하나와 시간 기준이 추가됨 |
| B. 삭제 | 일정 시간이 지나면 행을 지움 | 단순 | 흔적이 사라져 검증·분석 불가 |
| C. 이어하기 | 페이지를 다시 열면 하던 매치를 불러옴 | 사용자 경험 좋음 | 만들 것이 늘고, 끝내 돌아오지 않는 경우는 여전히 남음 |
| D. 페이지 종료 시 서버에 알림 | 브라우저 종료 이벤트로 중단 요청 | 즉시 반영 | 강제 종료·네트워크 끊김에서는 동작하지 않아 신뢰할 수 없음 |

## QA 권고안
**A안**: 마지막 활동 후 **10분**이 지나면 `ABANDONED`로 바꾸고, 매치 기록에는 "중단"으로 표시하며, 승률에서는 제외한다. 중단된 매치에 던지기가 오면 거부하고 ERROR log를 남긴다(R-08과 같은 방식).
테스트할 수 있도록 기준 시간은 설정값으로 둔다 (테스트 환경에서는 1분).

권고하면 명세에 들어갈 규칙 초안:
> R-10. 마지막 활동 후 10분이 지난 진행 중 매치는 중단(ABANDONED)으로 처리한다. 중단된 매치는 던지기를 거부하고(ERROR log), 승률 계산에서 제외한다.

## 재발 방지

- **조치**: 요구사항 검토 체크리스트에 **"이탈·중단·재시도 흐름"** 항목을 추가한다. 다음 기능부터는 명세 검토 단계에서 유저 시나리오 초안을 함께 쓴다.
