# SPEC-002 기간 필터에 시작일이 종료일보다 늦을 때의 처리 규칙이 없음

| 항목 | 내용 |
|---|---|
| 유형 | **Spec Issue** (명세 누락 — 기대 결과를 정할 수 없음) |
| 상태 | **PO 결정 대기** |
| 관련 규칙 | [S-01](../01-requirements.md) 매치 기록 Grid는 닉네임·기간으로 필터 (입력 오류 처리 없음) |
| Blocked TC | [TC-F04](../02-test-cases.md) |
| 발견 경로 | 유저 시나리오 [US-04](../02-user-scenarios.md) 3단계 "실수로 시작일과 종료일을 거꾸로 넣는다" |
| 발견 | 2026-10-26 TC 작성 중, 2026-10-27 기능 검증에서 동작 확인 |
| 작성 | QA 김성환 · PO 역할도 작성자가 겸함 (포트폴리오 환경) |

## 현상
통계 화면에서 시작일 **2026-10-27**, 종료일 **2026-10-26**으로 조회하면 **안내 없이 0건**이 나온다 ("0 / 0건").
명세에 이 입력의 처리 규칙이 없어서, "조용히 0건"이 맞는 동작인지 판단할 수 없다.

## 영향
- 사용자는 "그 기간에 매치가 없다"고 **잘못 이해**한다. 입력 실수인지 데이터가 없는 것인지 구분할 수 없다.
- 기능 오류는 아니므로 영향은 작지만, 화면에 0건이 나오는 원인이 두 가지(데이터 없음 / 입력 오류)로 섞인다.

## 관련 부서에 묻는 질문
1. 시작일 > 종료일이면 **조회를 막을까**, 안내 문구를 보여줄까, **두 날짜를 자동으로 바꿔** 조회할까?
2. 날짜 하나만 넣은 경우(시작일만, 종료일만)의 의미도 명세에 적을까? (현재: 시작일만 → 그날 이후 전부, 종료일만 → 그날까지 전부)

## 개선안 비교

| 안 | 내용 | 장점 | 단점 |
|---|---|---|---|
| A. 안내 후 조회 안 함 | "시작일이 종료일보다 늦습니다" 문구, 표는 그대로 | 사용자가 실수를 바로 앎 | 한 번 더 입력해야 함 |
| B. 자동으로 뒤바꿔 조회 | 두 날짜를 바꿔 조회하고 바꿨다고 안내 | 사용자 수고 없음 | 의도와 다를 수 있음 |
| C. 현행 유지 (0건) | 명세에 "0건으로 보여준다"고만 적음 | 구현 변경 없음 | 오해 가능성 그대로 |

## QA 권고안
**A안**. 화면에서 조회 버튼을 누를 때 검사하고, API도 `date_from > date_to`면 400으로 거부해 화면·API 동작을 일치시킨다.
명세 S-01에 추가할 문장 초안:
> 시작일이 종료일보다 늦으면 조회하지 않고 "시작일이 종료일보다 늦습니다"를 표시한다. API는 400으로 거부한다.

## PO 결정
- 상태: **대기** (작성자가 PO 역할 겸임. 결정 후 이 칸에 날짜·내용·반영 버전을 적는다)
- v1.0은 현행 유지

## 재발 방지
- **놓친 이유**: S-01을 정상 입력 기준으로만 썼다. 입력 칸이 2개 이상인 필터에서 **입력 사이의 관계**(순서, 범위)를 검토하지 않았다.
- **조치**: 요구사항 검토 체크리스트에 **"입력 순서가 뒤바뀐 경우, 값 사이의 관계"** 항목을 추가한다.
